第三部分：整个系统的代码（极简版）
存储层
class ChampionStorage {
  constructor(nodes) {
    this.nodes = nodes;
    this.champion = null;
  }
  
  async write(key, value) {
    while (true) {
      const target = this.champion || this.nodes[Math.floor(Math.random() * this.nodes.length)];
      try {
        await target.client.set(key, JSON.stringify(value));
        this.champion = target;
        return;
      } catch {
        this.champion = null;
      }
    }
  }
  
  async read(key) {
    if (!this.champion) return null;
    try {
      return await this.champion.client.get(key);
    } catch {
      this.champion = null;
      return null;
    }
  }
}

调度层（同样的模式）
class ChampionScheduler {
  constructor(instances) {
    this.instances = instances;
    this.leader = null;
  }
  
  async execute(task) {
    while (true) {
      const target = this.leader || this.instances[Math.floor(Math.random() * this.instances.length)];
      try {
        const result = await target.run(task);
        this.leader = target;
        return result;
      } catch {
        this.leader = null;
      }
    }
  }
}

第五部分：为什么这样能工作（自洽性证明）
你的担心	实际答案
读到旧值怎么办？	读的永远是冠军，冠军就是最后写成功的那个
冠军切换时数据丢失？	丢失就是任务失败，重试即可，不会变成错误数据
需要数据同步？	不需要，新任务写新冠军，旧数据不重要
脑裂怎么办？	短暂两主时只有一个能写成功，另一个自动失效
所有节点都挂了？	业务停摆，等待恢复；一旦有节点恢复，随机重试就会命中
